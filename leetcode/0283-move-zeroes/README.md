# Move Zeroes（移動零）

> LeetCode 283｜Easy｜建議在 Day 07 之後｜技巧：雙指標、原地修改陣列

## 題目

給你一個整數陣列 `nums`，把所有的 `0` 移到陣列最後面，其他數字保持原本的先後順序。

- **直接修改傳進來的陣列**，不可以另外做一個新陣列回傳。函式不回傳任何東西，回傳型別是 `void`。
- 陣列至少有 1 個數字。

| 呼叫前的 `nums`      | 呼叫後的 `nums`      |
| -------------------- | -------------------- |
| `[0, 4, 0, 0, 7, 2]` | `[4, 7, 2, 0, 0, 0]` |
| `[9, 0, 3]`          | `[9, 3, 0]`          |
| `[0, 0]`             | `[0, 0]`             |
| `[5, -1]`            | `[5, -1]`            |

呼叫的方式和主線不太一樣：結果不在回傳值裡，而是在原本的陣列裡。

```ts
const numbers = [9, 0, 3];
moveZeroes(numbers); // returns nothing
console.log(numbers); // [ 9, 3, 0 ]
```

## 先想一想

1. 用 Day 04 學的寫法，你會怎麼做出「0 都在最後面」的陣列？那個做法哪裡不符合這題的要求？
2. 把非零的數字往前排時，第一個非零的數字該放到位置幾？第二個呢？你需要多記住哪一個數字？
3. 非零的數字都排好之後，後面剩下的位置應該變成什麼？

## 解法一：直覺做法

先用 Day 04 的 `filter` 做出排好的新陣列，再一格一格抄回 `nums`：

```ts
function moveZeroesWithCopy(nums: number[]): void {
  const arranged = [
    ...nums.filter((value) => value !== 0),
    ...nums.filter((value) => value === 0),
  ];
  for (const [i, value] of arranged.entries()) {
    nums[i] = value;
  }
}
```

- 最後一段一定要抄回 `nums`。題目檢查的是呼叫的人手上那個陣列，`arranged` 在函式結束後就沒有人拿得到了。
- `entries()` 同時給出位置和元素，在 [0001 Two Sum](../0001-two-sum/README.md) 介紹過。

慢在哪裡：時間上還算快，但它多做了一個和 `nums` 一樣長的新陣列。題目要求原地修改，就是不想多花這一份記憶體；陣列有一百萬個數字，就要多佔一百萬格。

## 解法二：雙指標，原地往前搬

用兩個「位置」一起往右走：

- **讀**：`for...of` 本身就是第一個指標，每一圈往右讀一個數字 `value`。
- **寫**：`write` 是下一個非零數字該放的位置。只有真的寫了一個數字，它才往右一格。

規則只有一條：讀到非零的數字，就寫到 `write` 的位置，`write` 加 1；讀到 0 就什麼都不做。讀完之後，`write` 前面全是非零的數字，`write` 和它後面全部補成 0。

```ts
export function moveZeroes(nums: number[]): void {
  let write = 0; // next position for a non-zero value
  for (const value of nums) {
    if (value !== 0) {
      nums[write] = value;
      write++;
    }
  }
  for (let i = write; i < nums.length; i++) {
    nums[i] = 0;
  }
}
```

以 `[0, 4, 0, 0, 7, 2]` 為例：

| 讀到的位置 | `value` | 做的事           | 之後的 `nums`        | `write` |
| ---------- | ------- | ---------------- | -------------------- | ------- |
| 0          | `0`     | 跳過             | `[0, 4, 0, 0, 7, 2]` | 0       |
| 1          | `4`     | 寫到位置 0       | `[4, 4, 0, 0, 7, 2]` | 1       |
| 2          | `0`     | 跳過             | `[4, 4, 0, 0, 7, 2]` | 1       |
| 3          | `0`     | 跳過             | `[4, 4, 0, 0, 7, 2]` | 1       |
| 4          | `7`     | 寫到位置 1       | `[4, 7, 0, 0, 7, 2]` | 2       |
| 5          | `2`     | 寫到位置 2       | `[4, 7, 2, 0, 7, 2]` | 3       |
| 第二個迴圈 |         | 位置 3 到 5 補 0 | `[4, 7, 2, 0, 0, 0]` | 3       |

幾個重點：

- `nums[write] = value` 只改 `write` 那一格，**不會**把原本的位置清成 0。所以中間會暫時出現 `[4, 4, ...]` 這種重複，這沒關係，第二個迴圈會把多出來的舊值補成 0。
- 一邊用 `for...of` 讀、一邊改同一個陣列，為什麼不會出錯？因為 `write` 永遠不會跑到讀的位置右邊，寫進去的格子都是已經讀過的，不會蓋掉還沒讀到的數字。
- 參數型別是 `number[]`，沒有 `readonly`。如果寫成 `readonly number[]`，`nums[write] = value` 會被 TypeScript 擋下來，因為 `readonly` 的意思就是「這個函式不會改它」。

> ▶ 動畫演示：[讀的位置一路往右，write 只在搬了數字時才前進](https://vincentlin0619.github.io/ts-engineer-bootcamp/leetcode/0283-move-zeroes/#anim-leetcode-0283-move-zeroes)

### 為什麼這題要改原本的陣列？

主線從 Day 04 開始一直強調「不改舊陣列，回傳新陣列」，這題卻反過來。兩種寫法都是對的，要看情況選：

|            | 不可變更新（主線的寫法）                              | 原地修改（這題的寫法）                                      |
| ---------- | ----------------------------------------------------- | ----------------------------------------------------------- |
| 做法       | 回傳新陣列，舊陣列不動                                | 直接改傳進來的陣列                                          |
| 好處       | 呼叫的人不會被嚇到；舊資料還在，容易比較、除錯、測試  | 不用多一份記憶體，資料很大時省很多                          |
| 風險       | 每次都複製，資料很大或改很多次時比較耗記憶體          | 所有指向同一個陣列的變數都會看到改變（Day 04 的值與參考）   |
| 適合的時候 | 一般的應用程式、Todo 這類很多地方共用的資料，預設用它 | 題目或 API 明確要求、陣列是自己剛建立的、效能真的有差的時候 |

寫原地修改的函式時，要讓別人一眼看出來：

- 參數寫 `number[]`，不寫 `readonly number[]`。
- 回傳型別寫 `void`，表示「結果在原本的陣列裡，不在回傳值」。
- 不要一邊改傳進來的陣列，一邊又回傳它，呼叫的人會分不清楚該用哪一個。
- JavaScript 內建的 `sort()` 和 `reverse()` 也是原地修改。很多人以為它們會回傳新陣列，結果把共用的資料改掉了。

## 複雜度

Big-O 用來描述「資料量變大時，花費怎麼跟著變大」。O(n) 的意思是：資料量變成兩倍，執行時間大約也變成兩倍；O(1) 是不管資料多大，花費都差不多。

| 解法                 | 時間 | 額外的記憶體 |
| -------------------- | ---- | ------------ |
| 解法一：做新陣列再抄 | O(n) | O(n)         |
| 解法二：雙指標       | O(n) | O(1)         |

- 兩種解法都只把陣列走固定幾遍，時間都是 O(n)。
- 解法一多做了一個長度 n 的陣列；解法二只多用了 `write`、`i` 兩個變數，陣列再大也一樣。這正是題目要求原地修改的原因。
